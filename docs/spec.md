# 音声研究日誌 仕様書

## 1. 目的と範囲
- マイクに話した内容を文字起こしし，Claude API で「日記らしい文章」にまとめて，その日の記録として保存する．
- 動作は単一の HTML ファイル（`index.html`）だけで完結させ，サーバーは使わない．データはブラウザの localStorage に保存する．
- **録音した音声そのものは一切保存しない**（扱うのは文字起こし結果のテキストだけ）．
- Claude API が使えない場合（キーがない，ネットワークエラー，拒否など）でも，原文のまま記録できること．

## 2. 動作環境
- Chrome／Edge の最新版．音声認識には Web Speech API（`window.SpeechRecognition || window.webkitSpeechRecognition`）を使う．
  - 設定は `lang = "ja-JP"`，`continuous = true`，`interimResults = true`．
  - 確定した結果を文字起こし欄に追記していく．途中経過（interim）は欄の下に薄い色で表示する．
  - 録音中にブラウザ側が認識を止めた場合（`onend`）は，停止ボタンが押されるまで自動で再開する．
- 音声認識が使えないブラウザでは録音ボタンを無効にして理由を表示し，テキスト入力だけで記録できるようにする．

## 3. 画面
1ページを4つのタブで切り替える：**記録／見返す／週次報告／設定**．

### 3.1 記録
| 要素 | 仕様 |
|---|---|
| モード切替 | 「日記」と「研究日誌」の2択．最後に選んだモードを設定に保存する |
| 日付 | `<input type="date">`．初期値は今日（端末のローカル日付） |
| 録音ボタン | 開始と停止を切り替える．録音中であることを表示する |
| 文字起こし欄 | `<textarea>`．音声で入った文字はここに追記され，手で編集もできる |
| まとめて保存 | Claude で要約してから保存する．APIキーがないときは押せない |
| 原文のまま保存 | 要約せずに，文字起こしを summary として保存する |

- 保存の対象になる記録がすでにある場合（同じ日付とモード）は，その旨を表示する（「この日の研究日誌に追記します」など）．
- 保存に成功したら文字起こし欄を空にし，保存した結果を表示する．
- 要約中はボタンを無効にし，「まとめています…」と表示する．

### 3.2 見返す
- **月カレンダー**：前月と翌月に移動できる．記録がある日には印を付け，研究日誌と日記で色を変える（両方ある日は2つ表示する）．日付を押すと，その日の記録の詳細を開く．
- **一覧**：日付の新しい順に並べる．絞り込みは「すべて／日記／研究日誌」．各行には日付，モード，summary の冒頭約80文字を表示する．
- **詳細・編集**：
  - summary を `<textarea>` で編集して保存できる．
  - 「追記」欄にテキストを入力（録音でも可）し，5章の追記ルールで追加できる．
  - transcript（原文）は折りたたんで表示し，こちらも編集できる．
  - 削除するときは確認ダイアログを出す．

### 3.3 週次報告
- 基準日（初期値は今日）を選んで「生成」を押すと，**基準日を含む過去7日分（基準日−6日〜基準日）の研究日誌**から報告を作る．
- 対象の記録が0件のときは API を呼ばず，「対象の研究日誌がありません」と表示する．
- 結果は `<textarea>` に表示し，「コピー」ボタンでクリップボードにコピーできる．履歴は保存しない．
- APIキーがないときは「生成」ボタンを押せない．

### 3.4 設定
- APIキー：`type="password"` で入力する．「保存」と「削除」のボタンを置く．保存されているかどうかだけを表示し，キー自体は表示しない．
- モデル：テキスト入力で，初期値は `claude-opus-5-5`．
- 注意書き：「APIキーはこのブラウザにだけ保存されます．共有の PC では使わないでください」．

## 4. データモデル
localStorage を使う（すべて JSON 形式）．

`researchDiary.v1.entries`：Entry の配列
```json
{
  "id": "2026-11-20_research",
  "date": "2026-11-20",
  "mode": "research",
  "transcript": "話した原文（追記は区切り線で連結）",
  "summary": "まとめた文章（Markdown 文字列）",
  "summaryEdited": false,
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601"
}
```
- `mode` は `"diary"` か `"research"`．`id` は `${date}_${mode}` とし，日付とモードの組み合わせごとに1件にする．
- summary は**必ず小見出しで始まる** Markdown にする．AI が話題ごとに小見出しを付ける（話題が1つなら1つ，2つ以上なら話題の数だけ付ける）．
  - 日記：`## <話題の小見出し>` の下に本文の段落を書く．
  - 研究日誌：`## <話題の小見出し>` の下に，話した内容を箇条書き（`- `）で書く．小見出しの下にさらに見出しは作らない．
  - 「原文のまま保存」の場合は小見出しを `## メモ（HH:MM）` とする（AI を使わないため）．

`researchDiary.v1.settings`
```json
{ "apiKey": "", "model": "claude-opus-5-5", "lastMode": "research" }
```
- 読み込んだ JSON が壊れていたら空のデータとして扱い，元の文字列は `researchDiary.v1.entries.broken` に退避する（データを黙って失わないため）．

## 5. 保存と追記のルール
- 区切り線は `\n\n---（HH:MM 追記）\n\n`．
- summary の表示（記録の結果，詳細画面，週次報告）では，簡易 Markdown を整形して表示する．対応するのは `#`／`##`／`###` の見出し，`- ` の箇条書き，`---` の区切り線，空行で区切った段落だけ．HTML は必ずエスケープする．編集するときは Markdown の原文を `<textarea>` で扱う．
- **新規**：transcript ＝ 入力したテキスト，summary ＝ 要約（または原文）．
- **既存の記録に追記**：
  - transcript ＝ 既存の transcript ＋ 区切り線 ＋ 入力したテキスト．
  - 「まとめて保存」の場合は，**追記したあとの transcript 全体**からまとめ直して summary を置き換える．
    - ただし，ユーザーが summary を手で編集していた場合は，それを失わないよう確認ダイアログを出す（「手で直した内容を上書きします」）．手で編集したかどうかは `summaryEdited: true` で記録する．
  - 「原文のまま保存」の場合，および API が失敗した場合は，summary ＝ 既存の summary ＋ `\n\n## メモ（HH:MM 追記）\n\n` ＋ 入力したテキスト（追記部分も小見出しで始める）．
- 入力が空（空白だけを含む）のときは保存しない．

## 6. Claude API
- 公式 SDK `@anthropic-ai/sdk` を jsDelivr の ESM 版から `import` する：`https://cdn.jsdelivr.net/npm/@anthropic-ai/sdk@1.4.0/+esm`．
- `new Anthropic({ apiKey, dangerouslyAllowBrowser: true })` で初期化する．
- リクエスト：
  - `model`：設定の値（初期値は `claude-opus-5-5`）
  - `max_tokens: 16000`
  - `output_config: { effort: "low" }`（文章の要約なので low で足りる）
  - `thinking` は指定しない（このモデルでは無効化できない）
  - 拒否されたときのために，サーバー側のフォールバックを有効にする：`client.beta.messages.create({ ..., betas: ["server-side-fallback-2026-07-01"], fallbacks: "default" })`
- 応答の処理：まず `stop_reason` を確かめる．`"refusal"` のときは失敗として扱う．それ以外のときは `content` に含まれる `type === "text"` のブロックを連結した文字列を結果とする（`fallback` などほかの種類のブロックは無視する）．
- AI の出力が `#` で始まっていない場合は，日記・研究日誌とも先頭に `## メモ` を付けて保存する（必ず小見出しで始まるようにするため）．
- 失敗時（例外，`refusal`，空の応答）：理由を表示し，**入力内容は消さない**．そのうえで「原文のまま保存しますか？」と確認して，保存できるようにする．

### 6.1 プロンプト（system）
共通の前置き：
> あなたはユーザーの音声メモを整える編集者です．入力は音声認識の結果なので，誤変換やフィラー（えー，あの等）が含まれます．明らかな誤変換は文脈から直し，フィラーは除いてください．**入力に書かれていない事実・感想・予定を付け足さないでください．** 出力は本文だけにし，前置きや説明は付けないでください．

小見出しの規則（日記・研究日誌で共通）：
> 出力は必ず `## ` で始まる小見出しから書き始めてください．入力に含まれる話題を判断し，話題が1つなら小見出しを1つ，2つ以上なら話題ごとに小見出しを分けてください．小見出しは内容を表す短い言葉（15文字程度まで）にします．

日記モード：
> 一人称の「だ/である」調で，その日の出来事と気持ちが伝わる自然な日記の文章にまとめてください．各小見出しの下には段落で本文を書きます．

研究日誌モード：
> 研究日誌としてまとめてください．各小見出し（話題）の下には，話した内容を「- 」で始まる箇条書きで書きます．1項目は1つの事柄にし，簡潔な「だ/である」調にします．小見出しの下にさらに見出しを作らないでください．

週次報告：
> 以下は研究室の学生の直近1週間の研究日誌です．ゼミで報告するための週次報告を，次の3つの見出しだけを持つ Markdown で作ってください：`## 今週やったこと` `## 課題` `## 来週の予定`．各見出しの下は「- 」で始まる箇条書きにします．わかったことや結果は「今週やったこと」の項目に含めてください．該当する内容がない見出しには「- （記載なし）」と書いてください．重要な点を優先して簡潔にまとめ，各項目の末尾に元になった日付を `(11/18)` のように付けてください．日誌にないことは書かないでください．

user メッセージ：
- 日記・研究日誌：`日付: YYYY-MM-DD\n\n<文字起こし全文>`
- 週次報告：日付の昇順で `### YYYY-MM-DD\n<summary>` を連結したもの（期間を先頭に `期間: YYYY-MM-DD〜YYYY-MM-DD`）

## 7. プライバシー
- APIキーはこのブラウザの localStorage にだけ保存する．外部への送信先は Anthropic API だけ．
- 音声データは保存も送信もしない（Web Speech API の認識処理はブラウザが行う．Chrome では Google のサーバーで処理される旨を設定画面に書いておく）．

## 8. 範囲外
端末間の同期，検索，音声ファイルの保存，複数ユーザー，JSON の書き出しと読み込み，週次報告の履歴，5章にない Markdown 記法（太字，リンク，表など）の整形．

## 9. 受け入れ基準
- [ ] 録音を始めて話すと，文字起こし欄に日本語が追記される．停止すると認識が止まる．
- [ ] 音声認識が使えないブラウザでも，テキスト入力から保存できる．
- [ ] 日記モードで「まとめて保存」すると，小見出しで始まる日記らしい文章として保存される．
- [ ] 研究日誌モードで「まとめて保存」すると，話題の小見出しの下に，話した内容が箇条書きで並ぶ文章として保存される．
- [ ] 2つの話題を話すと，小見出しが2つに分かれる．
- [ ] 小見出しと箇条書きが整形されて表示される．
- [ ] 同じ日付・同じモードで2回保存すると1件にまとまり，transcript が区切り線で連結される．
- [ ] 同じ日付に日記と研究日誌を1件ずつ持てる．
- [ ] APIキーがない，または API が失敗した場合でも，原文のまま保存でき，入力が失われない．
- [ ] カレンダーに記録のある日が色分けして表示され，日付を押すと詳細が開く．
- [ ] 一覧がモードで絞り込める．
- [ ] 詳細画面で summary と transcript の編集，追記，削除ができ，再読み込みしても反映されている．
- [ ] 週次報告が基準日から7日分の研究日誌だけで生成され（日記と範囲外の日は含まない），コピーできる．
- [ ] localStorage に音声データが保存されていない．
- [ ] `node --test` がすべて通る．
